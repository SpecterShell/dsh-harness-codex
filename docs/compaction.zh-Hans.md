# 压缩

[English](compaction.md)

长对话会被压缩，让工作能在模型的上下文窗口内继续。预设把 DSH 自带的引擎替换为一个遵循 Codex 规则的本地引擎：模型收到一份摘要，然后是固定预算以内的最新用户消息。

## 工作方式

上下文估计达到模型窗口的 90% 时，引擎在下一步之前运行压缩；`/compact` 可以随时手动触发。

引擎用 Codex 的压缩提示词让模型对可压缩的对话范围做摘要，然后按下面的顺序重建上下文：

1. 开头的系统和开发者消息保持不变。
2. 在 20,000 token 以内的最新用户消息按时间顺序保留。文本按 UTF-8 字节除以四估算，跨越边界的消息保留开头和结尾，中间插入 `…N tokens truncated…` 标记。
3. 一条带有 Codex 摘要前缀的摘要消息跟在保留的消息之后。

范围内的工具结果、Agent 步骤和其他内容都会被丢弃。旧的摘要会被新摘要替换，不会叠加。token 数是估算值，因为 DSH 的计量器只统计整条消息。

## 失败时的行为

自动压缩如果不会缩小上下文就会被跳过，在有新内容之前不会重试。摘要失败或被取消时上下文保持原样，会话保存失败会如实报告，不会留下一个错误的结束标记。`/compact` 手动压缩总是照常执行。

原始事件保留在会话日志里。压缩替换的是下一次请求所用的上下文表面，日志中每条原始消息、摘要和替换记录都完整保留。

## 与 Codex 的一致程度和剩余差异

触发比例、20,000 token 预算、截断标记和压缩提示词都与 Codex 的 [ca21fe65](https://github.com/openai/codex/tree/ca21fe65d18a9b6326759fb4263c65dfbb645aa5) 提交一致。剩余的差异列在 [differences.zh-Hans.md](differences.zh-Hans.md)：Codex 还可以按单独的回合结束阈值或在后台压缩，并且会从会话配置重建开头上下文，而本预设保留 DSH 的系统和开发者消息。

## 设置

压缩没有面向用户的设置项。触发比例和预算沿用 Codex 的默认值。ChatGPT 订阅的云端压缩属于服务商插件的功能，不在本包范围内。
